# 実験再構成メモ: 埋め込みパターン回復を主軸にする

## 1. 何を言いたいか

現状の比較実験は、

- 「提案手法が定義した GT を既存手法が再現できるか」
- 「提案手法の出力を既存手法が近似できるか」

という構図が強い。

これでも技術的には正しいが、読者には
「提案手法に都合のよい定義を置いて、その定義に他手法が合わないことを示している」
ように見えやすい。

そこで主張の中心を次に置き換える。

- **提案手法は、ノイズや他の共起に埋もれた局所的な埋め込みパターンを、パターンと位置の両方の意味で回復できる**
- **既存手法は、パターンを見逃す・複数パターンを混ぜる・領域を粗くしか返せないため、埋め込みパターンを「ちゃんと」抽出できない**

ここで「ちゃんと」とは、少なくとも次の 2 条件を満たすことを意味させる。

1. 埋め込んだアイテム集合を正しく当てる
2. そのパターンが密である時空間領域を過不足なく当てる


## 2. 推奨する全体構成

### EX-A: 合成データによる比較実験

主張:

- 埋め込みパターン回復は提案手法の本丸であり、比較手法との差はここで示す

役割:

- 定量比較の主実験
- GT は提案手法出力ではなく、**埋め込んだパターンと埋め込んだ領域**に置く


### EX-B: 合成データによるスケーラビリティ評価

主張:

- 提案手法は埋め込みパターンを回復できるだけでなく、グリッド拡大や次元増大にも耐える

役割:

- 計算量・実用性の主実験
- ここでは planted pattern は不要。現行の密度ベース生成をそのまま使ってよい


### EX-C: 実データによる運用可能性・定性分析

主張:

- 提案手法が回復する局所パターンは、実データでも解釈可能で重要である

役割:

- 「そのパターンを取れることに意味があるのか」への回答
- 読者の納得を取る実応用パート


## 3. EX-A の設計

### 3.1 GT をどう置くか

GT は「全 dense pattern 集合」ではなく、埋め込んだパターンインスタンスとする。

- itemset GT: 埋め込んだパターン集合
- region GT: 各埋め込みパターンに対応する領域

必要なら補助的に dense-start 厳密解も計算してよいが、主評価は planted GT に置く。


### 3.2 どういう埋め込み方が必要か

単純な「孤立した 1 個の強いパターン」では弱い。
比較手法が苦手で、提案手法の強みが出る埋め込み方にする。

最低限、次の 4 系統を用意したい。

1. **局所埋め込み**
   背景ではまれだが、特定の時空間窓だけ高密度になるパターン

2. **重なり埋め込み**
   複数パターンが時間または空間で部分的に重なるケース

3. **共有アイテム埋め込み**
   例: `{A,B,C}` と `{A,B,D}` が異なる領域で密になるケース
   比較手法は `{A,B}` に潰れたり、1 つの block に混ぜたりしやすい

4. **背景ブロック内埋め込み**
   広い粗い dense block の中に、より意味のある狭い itemset pattern が埋まっているケース
   「block は見えるが pattern は disentangle できない」を示しやすい

この 4 系統があると、単なる recall ではなく
「見逃し」「混合」「粗視化」の 3 種類の失敗を見せられる。


### 3.3 評価指標

F1 だけだと弱い。少なくとも次を分けて見る。

1. **Pattern Recovery F1**
   埋め込み itemset を当てられたか

2. **Region IoU / mean Jaccard**
   埋め込み領域をどこまで正しく当てたか

3. **Instance Recovery Rate**
   「正しい itemset」かつ「IoU >= tau」の予測が 1 つでも対応した planted instance の割合
   これが「ちゃんと抽出できたか」の主指標になる

4. **Merge Rate**
   1 つの予測が複数 planted pattern をまとめてしまった割合

5. **Fragmentation Rate**
   1 つの planted pattern が多数の予測に割れてしまう度合い

提案手法の優位性は、

- Pattern F1 が高い
- Region IoU が高い
- Instance Recovery Rate が高い
- Merge / Fragmentation が低い

の 4 点で示すのがよい。


### 3.4 比較手法の見せ方

比較手法ごとの失敗モードを先に宣言しておくと読みやすい。

- Colocation / STCP-Miner:
  itemset は出せても、局所密集領域が曖昧
- M-Zoom / M-Biz / D-Cube / CatchCore:
  dense block は出せるが、埋め込み pattern を分離できず混合しやすい

つまり、

- `取れない` ではなく
- `埋め込みパターンを itemset と領域の両方で正しく切り出せない`

という言い方に寄せる。


## 4. EX-B の設計

EX-B は現行方針でよい。むしろ EX-A と分けた方がきれい。

- EX-A は「正しく取れるか」
- EX-B は「どこまでスケールするか」

現行の密度ベース生成はスケーラビリティ測定に向いているため維持する。

推奨する小構成:

1. `d`-scalability
2. `T_max`-scalability
3. `space_max`-scalability

加えるなら 1 本だけ:

4. `|I|`-scalability

理由:

- 本研究の差分は「局所密集領域検出」だけではなく「itemset 列挙」でもある
- 比較手法との根本差を出したいなら `|I|` の増加に対するコストは非常に説明力が高い

ただし比較手法まで含めて全面比較すると重いので、
まずは提案手法単独でもよい。


## 5. EX-C の設計

実データでは GT を厳密に置けないため、ここで baseline F1 を主役にしない方がよい。

推奨する問いは次の 2 つ。

1. **実データ上で実行可能か**
   実行時間、出力パターン数、代表例数

2. **得られたパターンは重要か**
   代表パターンの定性分析

定性分析では、単に「珍しい組合せ」ではなく、
**局所性があるから重要**だと説明する。

例:

- 犯罪データ:
  ある犯罪カテゴリの組が、特定の時期・地区でのみ密になる
- 311:
  苦情カテゴリの組が、季節や行政イベントに対応して局所的に現れる
- 地震:
  深さ・領域・時期がそろった局所パターンが、全期間集計では埋もれる

ここでのメッセージは、

- 提案手法が返すのは「余分なパターン」ではない
- **局所現象を見分けるために必要なパターン**

という点である。


## 6. なぜそのパターンが重要かの説明軸

論文中では次の 3 軸で説明すると通しやすい。

### 6.1 局所意思決定に必要

実運用では「全期間・全空間で平均的に関連するか」より、
「いつ・どこで・どの組合せが局所的に密になったか」の方が重要である。

### 6.2 集約すると消える

比較手法が返す global co-location や coarse block では、
埋め込みパターンが他の共起に吸収される。
その結果、実際に知りたい局所現象が見えなくなる。

### 6.3 itemset と領域は両方必要

pattern だけ分かっても、いつどこで起きたかが分からない。
領域だけ分かっても、何の組合せが効いているかが分からない。
提案手法の価値は、この 2 つを同時に返す点にある。


## 7. 現行構成からの具体的な変更案

### 変更した方がよい点

- 現行 EX-1 の中心を「実データ F1 vs 提案手法由来 GT」に置きすぎない
- 主比較は合成 planted experiment に移す
- 実データは実運用性と定性分析を前面に出す

### 残してよい点

- 現行 EX-2 の密度ベーススケーラビリティ
- dense-start 厳密解を使った補助評価
- 4 実データセットの幅広さ

### 推奨する章立て

1. EX-A: Synthetic embedded-pattern recovery
2. EX-B: Synthetic scalability
3. EX-C: Real-data applicability and qualitative analysis

この順なら、

- まず「何を正しく取れるか」
- 次に「それをどこまで速くできるか」
- 最後に「実データで意味があるか」

という自然な流れになる。


## 8. 既存実装との接続

流用元の候補:

- `experiments/run_experiments.py`
  planted dense region recovery の発想が残っている
- `experiments/run_ex2_scalability_v2.py`
  EX-B の土台としてそのまま使える
- `experiments/run_ex1_v2.py`
  EX-C の実データ解析パイプラインとして流用できる

つまり、完全に作り直すより

- EX-A を新設または旧 planted 実験を再設計
- EX-B は維持
- EX-C は主張を入れ替える

という方針が最も現実的。


## 9. 結論

一番重要なのは、比較実験の問いを

- 「提案手法の GT を再現できるか」

から

- **「埋め込まれた局所パターンを、pattern と region の両方の意味で正しく回復できるか」**

に変えること。

その上で、

- 合成比較で回復性能を示す
- 合成スケーラビリティで計算可能性を示す
- 実データ定性分析で重要性を示す

という 3 本立てにすると、論旨がかなり通しやすくなる。
