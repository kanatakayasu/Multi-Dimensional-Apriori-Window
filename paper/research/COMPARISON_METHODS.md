> 作成: 2026-04-09
> 対象論文: paper/C-multidimensional/dawak2026/
> 目的: 比較実験・Related Work に使える手法の候補整理

---

## 1. 多次元 AW の問題設定（比較の基準）

### 入力

- $d$ 次元トランザクション列 $\mathcal{D} = \{(\bm{c}_n, d_n)\}$
  - $\bm{c}_n \in \mathbb{R}^d$：座標ベクトル（第0軸=時間、第1軸以降=空間・カテゴリ）
  - $d_n \subseteq \mathcal{I}$：アイテム集合（トランザクション内容）
- ウィンドウ幅ベクトル $\bm{W}$、サポート閾値 $\theta$

### 出力

- **全パターン** $P \subseteq \mathcal{I}$ に対し、$P$ の **密集領域**（スライディングウィンドウサポート $\geq \theta$ の連結成分）を列挙

### 核心

1. セルの値は $I_P[\bm{b}] \in \{0,1\}$（パターン P がセル $\bm{b}$ に出現するかの指示関数）
2. Apriori 枝刈りは**探索空間の外側**に乗っかるだけ。セルレベルではスカラー二値テンソル
3. **真の新規性** = Apriori 枝刈りにより、$2^{|\mathcal{I}|}$ 個のパターンを全列挙せずに済む点

## 2. 検討した比較手法（全7種）

### 2.1 テンソル密ブロック検出族

#### M-Zoom（現在 EX-D に採用済み）

| 項目 | 内容 |
|------|------|
| 論文 | Shin, Hooi, Faloutsos. ECML/PKDD'16 / TKDD'18 |
| 手法 | 多次元テンソルから greedy に密ブロックを検出。各軸を交互に縮小 |
| 密度定義 | ブロック内の非ゼロ比率（質量 / 幾何平均密度など） |
| 入力 | スパーステンソル（スカラー値） |
| 出力 | 密ブロック座標 $(U_B, T_B, L_B, \ldots)$ |
| 理論保証 | 密度下界保証あり |
| 実装 | [GitHub: kijungs/mzoom](https://github.com/kijungs/mzoom) |

**多次元 AW との関係（重要）:**

- 固定パターン $P$ の二値テンソル $I_P$ を M-Zoom に渡せば、**密集領域検出として原理的に等価**
  - AW のサポート $S_P(\bm{s}) \geq \theta$ ↔ M-Zoom の密度 $\rho \geq \theta / |\bm{W}|$（閾値換算すれば同じ条件）
- **本質的な差**: M-Zoom はテンソル1つに対して密ブロックを1〜数個返す。全パターンを列挙するには $2^{|\mathcal{I}|}$ 回実行が必要 → Apriori 枝刈りなしで指数爆発
- 出力の形状差: M-Zoom は矩形ブロック（各軸の連続範囲）、AW は $2d$-近傍連結成分（非矩形可）

**論文での使い方**: EX-D に採用済み。「局所窓解像度の欠如」より「全パターン列挙に Apriori を使えないため指数コストになる」と説明する方が論理的に強い。

### 2.2 時空間共起パターンマイニング族

#### SpatialColocation / STCP-Miner

| 項目 | 内容 |
|------|------|
| 代表論文 | Shekhar & Huang. ACM GIS'01（静的 Colocation）<br>Qian & Yin. IEEE'09（重み付きスライディングウィンドウ版 STCP-Miner） |
| 手法 | 複数種フィーチャーが地理的近傍に共存するパターンを **Participation Index (PI)** で評価 |
| 時間対応 | 静的版は時間軸なし。STCP-Miner は重み付きスライディングウィンドウで時空間対応 |
| 問題設定 | トランザクション構造なし（連続空間上のポイントデータ） |

**多次元 AW との関係:**

- **複数アイテムの共起を扱う**点は最も近い競合
- PI は「全インスタンス中、共起するものの割合」でサポート閾値とは定義が異なる
- トランザクション単位の共起（同一取引内に A と B が存在）ではなく、空間的近傍の共起

**EX-D への採用可否**: **Related Work 言及推奨**（既に `\cite{shekhar2001colocation}` 引用済み）。STCP-Miner を加えれば「スライディングウィンドウ × 時空間共起」の先行研究として言及できる。実験化は変換コスト大で非推奨。

## 4. 手法空間における多次元 AW の位置づけ

### 2×2 マップ：空白地帯の可視化

```
                  時空間密集領域あり    時空間密集領域なし
                ┌─────────────────────┬──────────────────────┐
アイテム        │   ← 多次元 AW のみ  │ Apriori / FIM_global │
共起あり        │      (空白地帯)      │ STCP-Miner           │
                ├─────────────────────┼──────────────────────┤
アイテム        │ M-Zoom / SpecGreedy  │                      │
共起なし        │ SaTScan / ST-DBSCAN  │  （スコープ外）       │
                │ DenseAlert / D-Cube  │                      │
                └─────────────────────┴──────────────────────┘
```

- **右上（共起あり × 密集領域なし）**: Apriori 系・STCP-Miner。「何が共起するか」は分かるが「いつどこで」の密集構造は出力しない
- **左下（共起なし × 密集領域あり）**: M-Zoom 族・SaTScan・ST-DBSCAN。「いつどこで密か」は分かるがアイテム共起の概念がない
- **左上（共起あり × 密集領域あり）**: **多次元 AW のみ**。この領域を占める既存手法が存在しない = 論文の新規性の根拠

## 5. 多次元 AW の真の新規性（比較から導かれる整理）

### 以前の説明（弱い）

> 「M-Zoom はアイテムセット共起を扱えない」

### 正確な説明（強い）

> 「M-Zoom は固定パターン P の二値テンソル I_P に対して密集領域検出ができる（問題設定は実質同じ）。
> しかし全パターンを列挙するには M-Zoom を $O(2^{|\mathcal{I}|})$ 回実行する必要があり指数爆発する。
> 多次元 AW は Apriori 包含定理による枝刈りで $M \ll 2^{|\mathcal{I}|}$ 回に削減し、
> 全パターンの密集領域を $O(M \cdot G + N \cdot \prod_{k \geq 1} W_k)$ で一括列挙できる唯一のフレームワークである。」

### 計算量の対比

```
M-Zoom を全パターンに適用：
  O(2^|I| × (テンソルサイズ × 反復回数))   ← Apriori なしで指数オーダー

多次元 AW：
  O(M × G + N × ΠW_k)
  ここで M = Apriori 枝刈り後の実際のパターン数 << 2^|I|
```

## レビュー結果（TASK-2）

> 追記日: 2026-04-10
> 目的: 5手法について「d次元トランザクション密集領域検出の比較手法として本当に適切か」を判定

---

### 手法1: Colocation（SpatialColocation）

**問題設定の一致度: 低**

| 観点 | 評価 |
|------|------|
| アイテム共起を扱うか | ○（Participation Index で複数フィーチャーの共起を評価） |
| ウィンドウ内トランザクション共起か | ✗（空間的近傍共起。トランザクション単位の共起ではない） |
| 密集「領域」を出力するか | ✗（PI 値が閾値を超えるパターンを返すが、領域の空間的連結成分は出力しない） |
| 時間軸の扱い | ✗（静的版は時間なし） |

**比較として妥当な理由**: 複数アイテム（フィーチャー）の共起を扱うという点では本研究に最も意味的に近い先行研究群であり、Related Work §時空間パターンマイニング での位置づけ比較に有用。

**限界・注意点**:
- PI は「全インスタンス中共起する割合」でありスライディングウィンドウ内の絶対サポート（件数）とは定義が根本的に異なる。直接の精度比較はパラメータ変換が恣意的になる
- 連続空間上のポイントデータを前提としており、離散化済みグリッドへの適用は不自然
- トランザクション構造（同一トランザクション内に A と B）を仮定しないため、問題設定が異なる

**論文での説明が必要な点**: Colocation は「空間的近傍共起」を扱う手法であり、本研究の「ウィンドウ内トランザクション共起」とは問題定義が異なることを Related Work で明示する。直接の数値比較（EX）に含める場合は、この定義差を脚注・キャプションに記載すること。

---

### 手法2: STCP-Miner

**問題設定の一致度: 低〜中**

| 観点 | 評価 |
|------|------|
| アイテム共起を扱うか | ○（PI ベースの時空間共起） |
| スライディングウィンドウを使うか | △（重み付きスライディングウィンドウだが、矩形カウントではなく減衰重み付き PI） |
| 密集「領域」を出力するか | ✗（共起パターンリストを出力。空間的連結成分の概念なし） |
| 実装の妥当性 | 自前実装の場合、原著 PI 計算と本研究サポート定義の差が大きく、公平な比較が難しい） |

**比較として妥当な理由**: 「スライディングウィンドウ × 時空間 × 複数アイテム共起」という組み合わせで先行研究の中では最も問題設定が近い。Related Work に含め、本研究との設計差分を説明する根拠として使える。

**限界・注意点**:
- 減衰付き PI と絶対サポート閾値 θ は直接比較不能。パラメータ変換の仮定がレビュアーの疑問点になりやすい
- 自前実装のため、実験での比較はバグリスクと実装バイアスの懸念がある
- 公開実装が存在しないため再現性の確認が困難

**論文での説明が必要な点**: 自前実装を EX に含める場合は実装の詳細（PI 計算式、ウィンドウ設定）を付録に記載すること。Related Work 言及のみで十分な可能性が高い。

### 手法3: MZoom_dD

**問題設定の一致度: 中〜高（ただし重要な限界あり）**

| 観点 | 評価 |
|------|------|
| 密集ブロック検出 | ○（多次元テンソルから密ブロックを greedy 検出） |
| 固定パターン P の密集領域検出 | ○（二値テンソル I_P を渡せば原理的に同等） |
| 全パターン列挙 | ✗（Apriori なしで O(2^|I|) 回の実行が必要 → 指数爆発） |
| 出力形状 | △（矩形ブロック vs 2d-近傍連結成分で形状が異なる） |
| 理論保証 | △（密度下界保証あり、完全列挙保証なし） |

**比較として妥当な理由**: 密集ブロック検出という問題設定が最も近い族の代表。EX-D ですでに採用済み。「単一パターンの密集領域 vs 全パターン一括列挙」という本研究の貢献を際立たせる対比手法として最適。

**限界・注意点**:
- 全アイテムセットを列挙する比較実験では、MZoom_dD の実行回数が指数的になるため、比較対象パターン数を限定する必要がある
- 矩形ブロック（各軸が連続範囲）と本研究の連結成分は形状が異なるため、精度指標の定義に注意が必要（IoU ではなく発見された密集セルの F1 等を使うべき）
- greedy アルゴリズムのため最適解の保証がなく、θ を直接パラメータとして受け取れない点は論文で説明が必要

**論文での説明が必要な点**: EX での説明文に「MZoom_dD はパターンごとに個別実行する設定。Apriori 枝刈りがないため全パターン列挙は非現実的であり、代表的な少数パターンでの比較となっている」を明記すること。

### 手法4: ST-DBSCAN

**問題設定の一致度: 低**

| 観点 | 評価 |
|------|------|
| 密集領域を出力するか | ○（密度ベース連結クラスタを出力） |
| アイテム共起を扱うか | ✗（1種類のイベントの (x, y, t) ポイントデータのみ） |
| ウィンドウ定義 | ✗（ε近傍（球形）vs 矩形スライディングウィンドウ：定義が根本的に異なる） |
| 全パターン列挙 | ✗（Apriori なしで指数爆発） |

**比較として妥当な理由**: 時空間密集クラスタリングの代表手法として Related Work に言及することに意義がある。1パターン分の比較実験においては、共起セルをポイント列に変換することで形式的な比較は可能。

**限界・注意点**:
- ε-近傍と矩形ウィンドウはパラメータ変換が恣意的。ε = W/2 の正方形近似など変換仮定をおく必要があり、レビュアーからの突っ込みリスクが高い
- MinPts（密度閾値）と θ（絶対サポート）も定義が違い、同一条件設定が難しい
- アイテム共起の概念が根本的に欠けているため、EX での数値比較には不向き

**論文での説明が必要な点**: Related Work では「ST-DBSCAN は時空間クラスタリング手法であり、複数アイテムの共起と矩形ウィンドウという本研究の問題設定とは前提が異なる」と1文で説明すること。EX に含める場合はパラメータ変換の仮定を明示すること。

### 手法5: LISA（Local Indicators of Spatial Association）

**問題設定の一致度: 低**

| 観点 | 評価 |
|------|------|
| アイテム共起を扱うか | ✗（単変量空間自己相関指標。アイテムセットの概念なし） |
| 密集「領域」を出力するか | △（局所モラン統計量が有意な空間的クラスタセルを特定できる） |
| ウィンドウ構造 | ✗（空間的重み行列（queen contiguity 等）を使用。矩形スライディングウィンドウではない） |
| 時間軸の扱い | ✗（基本的に1時点のスナップショット分析） |

**比較として妥当な理由**: 空間的集中を統計的に評価するアプローチとして Related Work §空間統計 に言及することに意義はある。しかし、アイテムセット共起という本研究の核心概念が完全に欠如しているため、EX での比較は不適切。

**限界・注意点**:
- LISA（Moran's I 局所版）は各セルの値が空間的に自己相関しているかを検定するもので、複数アイテムの同時出現を評価する設計になっていない
- PySAL `esda.Moran_Local` で実装可能だが、アイテムセット P を単変量スカラーにどう変換するか（例: P の出現件数）が恣意的
- 統計的有意性検定ベースであり、サポート閾値 θ との直接比較はできない
- 時間軸がないため、時空間密集領域という本研究の出力とは根本的に異なる

**論文での説明が必要な点**: LISA は Related Work から外すか、「空間統計手法は単変量・統計検定ベースであり本研究の問題設定（多変量アイテムセット × 矩形スライディングウィンドウ）とは前提が異なる」と一括説明する形で整理すること。EX への組み込みは推奨しない。

| 手法 | 一致度 | EX 組み込み | 推奨扱い |
|------|:------:|:-----------:|---------|
| Colocation | 低 | 不推奨 | Related Work に言及のみ |
